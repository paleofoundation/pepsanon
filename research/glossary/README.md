# Peptide glossary editorial and implementation record

The glossary contains 54 terms. `lib/data/glossary.json` is the authored source of truth. Every definition and explanatory paragraph carries a source identifier and a passage or methods locator. Definitions are plain-language paraphrases, not verbatim quotations. Study-specific observations retain the population, preparation, route and outcome boundaries of the cited research. The immunogenicity entry identifies its supplementary FDA definition explicitly; study-design terminology also cites the CONSORT methods paper.

Source work used the site's existing cited papers and the local primary-paper packet, with additional cited primary papers for foundational concepts. Packet filenames and verified DOIs are retained with the relevant sources. No consumer dose, injection protocol, new effect-size calculation, or product-quality threshold was derived. This is an AI-assisted selected-source glossary, not a clinically peer-reviewed reference.

`term-audit.json` records recurring terms in the actual prose of the eight peptide guides and their question answers. Counts are blocks containing a term or alias, not raw word counts. Navigation, reference titles, and the new glossary are excluded. Additional terms with no current guide-prose match explain prerequisites in the cited papers and connect through related entries. Stack-guide backlinks are also generated at render time.

Run `node scripts/build-glossary-index.mjs` after editing glossary content, then `node scripts/check-glossary.mjs`. The latter validates citations, source locations, routes, related links, index consistency, and the prose-link matcher, and regenerates the recurrence audit. It verifies structural integrity, not scientific entailment. Source claims still require editorial review against the cited passages.

Internal prose links are generated only from text passed through the existing `CitedText` renderer. Matching prioritizes the longest phrase, honors word boundaries and common hyphen forms, and links each term at most once per rendered block with a five-term cap. Existing headings, anchors, references and citation numbering are not rewritten. Glossary explanations use the same matcher while excluding self-links. Adding a term and regenerating the index makes it available to directory search, global search, prose links, related links and the sitemap.

Verification: TypeScript check; existing eight-guide citation audit; glossary integrity and matcher checks; HTTP 200 for all 54 entries; matching canonical URLs; all rendered glossary reference anchors resolve; unknown term returns 404; every glossary entry appears in the sitemap. Browser checks covered desktop directory search, empty results, clearing filters, category and letter filters, megamenu, a detail page with guide backlinks and references, and a 390px mobile detail page and navigation. Mobile detail width matched the viewport. Representative article and global search HTML retained glossary links and source markers.

Publication is prepared in an isolated checkout with only the glossary changes applied over the latest published source, preserving unrelated workspace edits.
